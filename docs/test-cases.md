# Library Management Test Cases

| ID | Title | Requirement | Preconditions | Steps | Expected | Priority | Type |
|---|---|---|---|---|---|---|---|
| TC-001 | Add a valid new book | REQ-1 | The library is available and the book ID does not already exist. | 1. Create a book with ID 101, name "Java Programming", author "James Gosling", and quantity 5. 2. Add the book to the library. | The book is added successfully with the correct ID, name, author, and quantity. | High | Positive / Functional |
| TC-002 | Reject duplicate book ID | REQ-2 | The library already contains a book with ID 101. | 1. Create another book with ID 101. 2. Attempt to add the book to the library. | The system rejects the duplicate book and the library still contains only one book with ID 101. | High | Negative / Functional |
| TC-003 | Reject malformed book ID | REQ-2 | The system is ready to add a new book. | 1. Enter an invalid book ID such as "ABC". 2. Attempt to add the book. | The system rejects the invalid book ID and does not add the book. | Medium | Negative / Functional |
| TC-004 | Issue book when copies are available | REQ-4 | A book exists with ID 101 and quantity 3. | 1. Select book 101. 2. Issue it to member Ali. 3. Check the quantity. | The book is issued successfully and its available quantity decreases from 3 to 2. | High | Positive / Functional |
| TC-005 | Prevent issuing unavailable book | REQ-5 | A book exists with ID 102 and quantity 0. | 1. Attempt to issue book 102 to member Ali. 2. Check the result and quantity. | The system rejects the issue request and the quantity remains 0. | High | Negative / Functional |
| TC-006 | Return a book currently on loan | REQ-6 | Book 101 is issued to member Ali. | 1. Return book 101 for member Ali. 2. Check the return result. | The system successfully records the return and removes the book from the member's issued records. | High | Positive / Functional |
| TC-007 | Reject return of book not on loan by member | REQ-6 | Book 101 is not currently issued to member Ali. | 1. Attempt to return book 101 for member Ali. 2. Check the result. | The system rejects the return because the book is not recorded as being on loan to Ali. | Medium | Negative / Functional |
| TC-008 | Member borrows at allowed limit | REQ-4 | A member is allowed to borrow up to the defined borrowing limit and has not reached it. | 1. Issue books to the member until the allowed limit is reached. 2. Check the member's issued books. | The member can successfully borrow books up to the allowed limit. | High | Positive / Functional |
| TC-009 | Member attempts to exceed borrowing limit | REQ-4 | A member has already reached the allowed borrowing limit. | 1. Attempt to issue one additional available book to the member. 2. Check the result. | The system rejects the additional borrowing request. | High | Negative / Functional |
| TC-010 | Calculate fine for zero days overdue | REQ-6 | A returned book has zero overdue days. | 1. Calculate the fine for 0 overdue days. 2. Check the calculated amount. | The system calculates a fine of 0 for zero overdue days. | Medium | Positive / Functional |
| TC-011 | Calculate fine for mid-range overdue period | REQ-6 | A book is overdue by a number of days within a normal fine range. | 1. Enter a mid-range overdue period such as 5 days. 2. Calculate the fine. | The system calculates the fine according to the defined fine rate for the selected overdue period. | Medium | Positive / Functional |
| TC-012 | Calculate fine at overdue-tier boundary | REQ-6 | The system has defined fine tiers with a boundary between two rates. | 1. Enter the exact number of overdue days at the tier boundary. 2. Calculate the fine. | The system applies the correct fine rate for the boundary value according to the defined tier. | High | Boundary / Functional |
